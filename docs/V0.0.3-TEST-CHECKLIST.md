# Crafting Core v0.0.3 — Live Test Checklist

## 1. Upgrade safety

- [ ] Update an existing v0.0.2 world to v0.0.3.
- [ ] Open a Character that already knew a v0.0.2 Recipe.
- [ ] Confirm the Recipe still appears in the Character Crafting tab.
- [ ] Craft it once and confirm materials/output still work.
- [ ] Confirm no legacy-knowledge error appears in console.

## 2. Private Compendium structure

As GM:

- [ ] Open Material Catalog and run **Create / Sync Materials**.
- [ ] Confirm the Compendium Directory contains a top-level **Crafting Core** folder.
- [ ] Confirm **Crafting Core — Materials** is inside it.
- [ ] Confirm Materials has internal folders for Creature Harvest, Gathering, and Profession & Trade with expected subfolders.
- [ ] Open **Learn Sources Library** or publish a Recipe and confirm **Crafting Core — Learn Sources** appears in the same top-level folder.
- [ ] Confirm Learn Sources contains Recipe, Formula, Blueprint, and Manual folders.

As a normal Player account:

- [ ] Confirm the Crafting Core Compendium packs do not appear in the Compendium Directory.
- [ ] Confirm the player cannot open/import from those packs.
- [ ] Confirm the GM Crafting Core administration button/UI is not exposed.

## 3. Material Catalog UX

- [ ] Confirm the UI clearly says **Built-in Curated Catalog** and does not imply the 119 defaults came from installed books.
- [ ] Test Search.
- [ ] Test Family, Nature, and Rarity filters.
- [ ] Edit one built-in material: change icon, chance, quantity and a metadata field.
- [ ] Close/reopen Material Catalog and confirm the override persists.
- [ ] Run Sync and confirm the override remains.
- [ ] Use **Reset Curated Default** and confirm curated metadata returns.
- [ ] Register a custom D&D5e Item and confirm it is copied as Loot → Trade Good and can be edited.

## 4. Publish lifecycle

Create a new Recipe draft with a real complex output Item (Item Creator output recommended).

- [ ] Save the draft.
- [ ] Confirm it is labeled Draft in the Recipe Builder list.
- [ ] Publish to the private Compendium.
- [ ] Confirm the Knowledge Source is created in the folder matching Recipe / Formula / Blueprint / Manual.
- [ ] Confirm the Builder draft shows Published.
- [ ] Confirm republishing updates the existing source rather than creating a duplicate.
- [ ] Delete the Builder draft.
- [ ] Confirm the published Knowledge Source still exists and works.

## 5. Rarity and price

For outputs of different rarities, publish Knowledge Sources and verify inheritance:

- [ ] Common → 50 gp
- [ ] Uncommon → 200 gp
- [ ] Rare → 2,000 gp
- [ ] Very Rare → 20,000 gp
- [ ] Legendary → 100,000 gp

Confirm the Knowledge Source uses the exact output rarity and there is no separate rarity selector.

## 6. Actor-bound autonomous knowledge

- [ ] Drag a published Knowledge Source from the GM-only Compendium to Character A.
- [ ] Use `Learn Recipe` and confirm the consumable is consumed normally.
- [ ] Confirm the Recipe appears in Character A's Crafting tab.
- [ ] Confirm Character B does not know it.
- [ ] Delete the Builder draft if it still exists; Character A must still know/craft it.
- [ ] Delete the physical Knowledge Source copy; Character A must still know/craft it.
- [ ] Optionally remove the source from the Compendium after learning; Character A's learned Recipe must remain usable.

## 7. Output snapshot regression

- [ ] Craft an Item Creator-produced consumable with Activities/Effects.
- [ ] Use the crafted Item.
- [ ] Confirm Item Creator runtime behavior remains intact.
- [ ] Confirm timed/Long Rest/Short Rest effects still belong to Item Creator and are not altered by Crafting Core.
