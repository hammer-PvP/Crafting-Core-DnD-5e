# Crafting Core v0.0.19 — Live Test Checklist

v0.0.19 is the Crafting Projects & Rest Progress release. Extra Effort is intentionally not included. Harvest / Scanner / Essence / Item Piles / normalization should behave exactly as in the validated baseline.

## 1. v0.0.18a regression fixes

- Learn several Recipes and confirm the left Crafting list shows the live `N×` craftable count again.
- Hide **Craftable Count** on one Recipe and confirm its `N×` value is not shown to the player.
- Publish a Recipe, then update/publish it repeatedly. Confirm the existing Learn Source contains exactly **one** `Learn Recipe` Activity after every update.
- Rename that Recipe and publish again. Confirm the same managed Compendium Item/Recipe identity is updated rather than accumulating another learning Activity.
- Republish one of the previously contaminated Learn Sources with multiple `Learn Recipe` Activities. Confirm it self-cleans to one Activity.

## 2. Simple Project lifecycle

Create a Project Recipe with no Progress Check and no Final Check.

- **1 Work Period / Long Rest:** Start Project should reserve ingredients, immediately perform the first work and produce the result in the same action.
- **2 Work Periods / Long Rest:** Start should leave the Project at 1/2. A Long Rest should not change it to 2/2 automatically; it should only enable **Work on Project**. Clicking Work should complete it.
- **3+ Work Periods:** repeat rests/work and confirm each compatible rest unlocks at most one Work Attempt.
- Reopen the Character sheet/world between steps and confirm Project state persists.

## 3. Rest cadence

- Long-Rest Project: Short Rest must not unlock work; Long Rest must unlock work.
- Short-Rest Project: either Short Rest or Long Rest must unlock one Work Attempt.
- Complete another rest while Work is already available and confirm it does not bank multiple Work opportunities.

## 4. One active Project + planning UI

- Start one Project.
- Select other known Recipes in the left list and confirm their ingredients/requirements can still be inspected.
- Confirm **Start Project** / legacy Craft is unavailable for another Recipe while one Project is active.
- Select the active Recipe and confirm Project state, progress bar (if visible), reserved materials and contextual controls appear in the right panel.

## 5. Material reservation / cancellation

- Start a Project and confirm its required ingredients are removed from available Actor inventory/craft counts.
- Cancel immediately and confirm all reserved materials return.
- Reserve multiple copies of a non-stackable/physical ingredient and confirm cancellation restores the correct count/items.
- Edit the Builder Recipe after the Project starts. Confirm the active Project keeps its original ingredients, work requirement, cadence and checks.

## 6. Progress Check — Every Work Period

Test all three failure outcomes with a deliberately high/low DC as needed.

### No Progress
- Failed Start/Work Attempt grants no +1, does not regress and does not lose materials.
- A new compatible rest is required before another normal Work Attempt.

### Regress Progress
- Configure **Progress Lost = 1**, then another test with 2+.
- Failed Work Attempt grants no +1 and reduces completed work by the configured amount, never below 0.
- No material is lost.

### Fail Project
- With **Lose Materials** off: failed check ends the Project and returns all reserved materials.
- With **Lose Materials** on: failed check ends the Project, loses the configured percentage and returns the rest.
- Important rounding case: ingredient requirement quantity 2 with 50% loss should lose exactly 1 total requirement, including when it was reserved from separate Item documents.
- Confirm there is no configuration/state where materials are lost while the same Project continues.

## 7. Progress Check — Midpoint Only

- Use 5 Work Periods: midpoint check should occur when attempting to reach 3/5.
- Use 6 Work Periods: midpoint check should occur when attempting to reach 3/6.
- Fail with No Progress/Regression and confirm the midpoint check is required again when crossing the midpoint later.
- Pass the midpoint, regress afterward if possible through the Final Check, then advance again and confirm the already-passed midpoint check is not repeated.

## 8. Final Crafting Check

Use a Project with a required Final Check.

- Reach full required work and confirm the first Final Check is available immediately.
- Success creates the result and consumes the reserved materials permanently.
- Relevant proficiency + **Automatic Success** should complete without a manual Final Check when the Actor qualifies.

### Stay Ready
- Fail Final Check: Project remains at full work, but Final Check becomes unavailable.
- Confirm repeated clicks cannot reroll immediately.
- Complete the compatible rest; confirm a new Final Check attempt becomes available.

### Regress Project
- Fail with regression 1, then 2+; confirm progress moves back by the configured amount and returns to normal Work mode.
- Confirm the next compatible rest is required before Work resumes.

### Fail Project
- Lose Materials off: Project ends and reserved materials return.
- Lose Materials on: Project ends and the configured percentage is lost.

## 9. Player Visibility

Create a Project Recipe and hide/reveal independently:

- Output
- Ingredients
- Ingredient quantities
- Craftable count
- Relevant proficiency / attempt policy
- Crafting time/cadence
- Current Project progress
- Progress Check
- Progress DC
- Progress-failure consequence
- Progress material-loss percentage
- Final Crafting Check
- Final DC
- Final-failure consequence
- Final material-loss percentage
- Additional Description

Confirm hidden details do not leak through the right panel, waiting labels, roll flavor, Project outcome chat, or requirement errors, while the hidden mechanics still execute.

## 10. Legacy Timed Recipes

- Use an existing pre-v0.0.19 Recipe without Project settings and confirm it remains Timed.
- No Final Check: normal timed craft completes as before.
- Final Check success/failure: v0.0.18 behavior and configured material loss remain unchanged.
- Timed craft and Project craft both respect the one-active-crafting-job rule.

## 11. Knowledge / Learning smoke test

- Follow Crafting Eligibility still blocks an ineligible Actor before the Knowledge Source is consumed.
- Anyone Can Learn still allows learning even when the Actor cannot craft.
- `Learn` label remains scoped to Crafting Core Knowledge Activities.
- Smith's Tools and other Skill/Tool labels remain full/localized labels, not internal IDs.

## 12. Harvest regression smoke test

Use a few of the previously validated lootable Actors and confirm:

- Token Harvest still opens/works.
- Essence behavior is unchanged.
- Existing NPC Loot modes are unchanged.
- Normalize + Firearm-to-Crossbow homebrew still behaves as before when enabled.

No Harvest-family file is intentionally changed by v0.0.19.
