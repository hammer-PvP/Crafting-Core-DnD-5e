# Crafting Core v0.0.18a — Live Test Checklist

This patch is a polish pass over v0.0.18 only. Do not test or expect v0.0.19 rest-based Crafting Projects here.

## 1. Recipe Builder UI

- Open Crafting Core with at least two saved Recipes.
- Click each Recipe in the sidebar.
- Confirm the active highlight aligns exactly with the clicked Recipe row/icon/name.
- Scroll the Builder down to **Items Consumed** and drop an Item.
- Confirm the same scroll position is restored after the rerender.
- Repeat with the **Crafted Item** Output drop zone.
- Repeat with remove Ingredient / clear Output / Crafting Resolution toggles and confirm local rerenders do not jump to the top.

## 2. Full Skill / Tool labels

- Configure `Smith's Tools` as a Relevant Proficiency and as the Crafting Check.
- Confirm the Builder selector displays `Smith's Tools`, not the internal ID `smith`.
- Learn the Recipe on a Character and inspect the Crafting tab.
- Confirm the Character UI also displays the full D&D5e label.
- Publish/update the Knowledge Source and confirm its Description uses the full label.

## 3. Additional Description + auto-generated Knowledge description

- Add optional Recipe description/flavor text.
- Configure multiple Ingredients with quantities and an Output.
- Publish or **Update Published Source**.
- Open the published Manual/Recipe Item.
- Confirm its Description is generated from Recipe data rather than only saying that it teaches the Recipe.
- Confirm visible Ingredients are listed automatically and quantities follow Player Visibility.
- Confirm the optional GM description appears only when its visibility toggle is enabled.

## 4. Player Visibility

Test a Recipe with all visibility toggles enabled, then selectively disable them and republish/relearn as needed.

Confirm each setting independently controls the Character Crafting tab and published Knowledge Source:

- Output
- Ingredients
- Ingredient Quantities
- Relevant Proficiencies
- Who Can Attempt
- Crafting Check
- Crafting DC
- Failure Consequence
- Failure Percentage
- Crafting Time
- Additional Description

Hidden values must remain mechanically enforced even when they are not displayed.

## 5. Character Crafting tab cleanup

- Select a learned Recipe.
- Confirm the Recipe selector contains only the Recipe name (no `1x`, `0x`, etc.).
- Confirm the large Recipe header shows only the Recipe image/name and no tiny `Output ×1` line beneath it.
- If Output visibility is enabled, confirm it appears as a normal detail row instead.
- If Ingredient Quantities are hidden but Ingredients are visible, confirm names remain visible without numeric counts.

## 6. Learning Access — Follow Crafting Eligibility

Create/update a Recipe with:

- Relevant Proficiency: Smith's Tools
- Who Can Attempt: Requires relevant proficiency
- Learning Access: Follow Crafting Eligibility

### Character without Smith's Tools

- Give the Character a fresh 1-use Knowledge Source.
- Use its **Learn Recipe** Activity.
- Confirm learning is rejected before consumption.
- Confirm the Item still has its use and is not auto-destroyed.
- Confirm no Recipe knowledge is added to the Actor.
- If Relevant Proficiencies visibility is ON, confirm the rejection identifies `Smith's Tools` by its full label.
- If Relevant Proficiencies visibility is OFF, confirm the rejection is generic and does not reveal the hidden requirement.

### Character with Smith's Tools

- Use a fresh Knowledge Source.
- Confirm the Activity dialog button reads **Learn**, not **Use Ability**.
- Confirm the Character learns the Recipe and the Knowledge Source consumes its configured use normally.

## 7. Learning Access — Anyone Can Learn

- Keep the same proficiency-gated Recipe but change Learning Access to **Anyone Can Learn**.
- On a Character without Smith's Tools, confirm learning succeeds.
- Open the Crafting tab and confirm crafting is still blocked by the Recipe's independent Who Can Attempt rule.

## 8. Failure visibility + material loss regression

Use a Recipe with a required Crafting Check and material loss.

- With Failure + exact percentage visible, fail the roll and confirm the configured percentage is reported and consumed.
- Hide only Failure Percentage, fail again, and confirm the message says some materials were lost without exposing the exact percentage.
- Hide Failure entirely, fail again, and confirm the user receives only a generic crafting failure notification/outcome.
- Confirm failure never creates Output and never starts the seconds-based crafting job.

## 9. Backward compatibility

- Open a Recipe created in v0.0.18 before this patch.
- Confirm it opens without migration errors.
- Confirm missing visibility metadata defaults to visible so prior presentation does not silently disappear.
- For a legacy Recipe with `Requires relevant proficiency` and no Learning Access metadata, confirm learning defaults to following crafting eligibility.
- Confirm old automatic-success Recipes still craft exactly as before when no Crafting Check is configured.

## 10. Frozen Harvest regression smoke test

- Harvest one or two previously validated lootable Actors.
- Confirm Token HUD Harvest, Essence generation, Item Piles corpse conversion, and the selected Existing NPC Loot mode behave exactly as in v0.0.17/v0.0.18.
- No Harvest/Scanner/Essence/normalization source file should have changed in this patch.
